# job-switch 품질 평가 리포트

> 상태: 2026-10-16. 측정 → 원인 → 한 가지 개선 → 전후 비교까지 했습니다. 모델 비교(Haiku/Sonnet)와 E2E 모드 판정은 아직입니다(→ 마지막 절).

## 요약 (면접용 5줄)

1. **문제** — AI가 이력 문장을 공고에 맞춰 다시 쓸 때 없는 사실을 지어내는 것을, 프롬프트 부탁 대신 구조(문장마다 근거 id, 서버의 숫자·영문 이름 검증)로 막았지만 실제로 얼마나 막히는지 몰랐습니다.
2. **측정** — 가상 포트폴리오·공고 24쌍으로 평가 세트를 만들고, 다른 계열 모델(Gemini)로 판정한 뒤 그 판정기 자체를 사람 블라인드 검수로 보정했습니다(1차 79건, 2차 75건).
3. **발견** — 근거 id 조작과 숫자 날조는 0이었지만, 보정한 날조율은 약 14%였고 서버 경고는 사람이 확인한 날조 31건 중 3건만 잡았습니다. 날조는 근거가 약한 요구사항에 맞춘 문장에 약 4배 몰렸습니다.
4. **개선** — 원인 하나(재작성 단계가 강한 근거와 약한 근거를 구분하지 않음)만 고쳐 같은 조건으로 1,212문장씩 비교하니, 사람 보정 날조율이 약 14%(7~27%)에서 약 2%(2~11%)로 줄었고, 대가로 직무 어휘 사용이 9%p 줄었습니다.
5. **다음** — 남은 날조의 3분의 2는 근거가 충분한 문장의 행동·용어 격상이라 기계 검사로는 못 잡습니다. 그래서 문장마다 근거를 보고 사용자가 채택·고치기·되돌리기를 고르는 화면을 만들었고(배포 전), 같은 측정 체계로 다음 수정을 검증합니다.

> 숫자를 말할 때는 범위를 함께: "표본이 작아 개선 전 7~27%, 개선 후 2~11% 범위이고, 범위 끝끼리 비교해도 감소는 유지됩니다."

## 무엇을 쟀나

- 대상: `supabase/functions/job-switch` — JD 분석(Haiku) → 근거 매칭(Sonnet) → 문장 재작성(Sonnet) → 서버 검증(`verifyProject`, 숫자·영문 용어만 확인)
- 데이터: 직접 만든 **가상** 포트폴리오 12개 × 공고 2개 = **24 케이스**. 실존 인물 데이터 없음
- 실행: `base-iso` — 격리 모드(정답 요구사항을 2단계에 그대로 넣어 1단계 오류를 분리), 케이스당 1회, 재작성 문장 **606개**
- 판단 주체를 항상 구분합니다
  - **[자동]** 코드로 센 것
  - **[사람]** 사람이 정한 정답 또는 사람이 검수한 것
  - **[LLM 판정]** 다른 계열 모델(Gemini)이 판정한 것 — 사람 검수로 정확도를 따로 잼

|---|---|---|

### 재작성(3단계) 날조 — 사람 검수 79건

판정 모델 `gemini-3.6-flash`(2 케이스는 3.7 혼용). 사람은 LLM 판정을 보기 전에 결정했습니다(블라인드).
표본은 **LLM 이 날조라 한 39문장 전부 + LLM 이 정상이라 한 567문장 중 무작위 40문장**입니다.
재현: `npm run eval:agreement` (데이터 `eval/review/judge-human.json`)

| | 사람 날조 | 사람 정상 |
|---|---|---|
| LLM 날조 | 27 | 12 |
| LLM 정상 | 4 | 36 |

| 지표 | 값 |
|---|---|
| 사람–LLM 일치 | 63/79 (79.7%) |
| LLM 판정 정밀도 | 27/39 = 69.2% (95% 53.6~81.4%) |
| LLM 이 놓친 비율 | 4/40 = 10.0% (95% 4.0~23.1%) |
| **보정한 전체 날조율** | **13.8% ≈ 84/606문장** (보수적 구간 7.2~26.8%) |
| **서버 검증기가 잡은 비율** | **사람이 날조로 본 31건 중 3건** |

- 검수 표본의 날조 비율(31/79)은 층화 표본이라 **전체 날조율이 아닙니다.** 전체는 층별 비율로 다시 가중한 13.8% 입니다.
- 서버가 잡은 3건 중 2건은 숫자·영문 용어가 든 문장(LCP 기준 충족, B2B SaaS)이었습니다. 서버 경고 중 사람이 정상으로 본 것은 1건 있었습니다.
- LLM 판정만 쓰면 날조율을 6.4%(39/606)로 보게 되는데, 사람 검수로 보정하면 약 2배입니다. LLM 판정은 과하게 잡는 쪽(오탐 12)과 놓치는 쪽(4/40)이 동시에 있습니다.

### 놓친 날조 유형 [사람 코멘트 기준]

모두 한글 주장이라 숫자·영문 용어만 보는 서버 검증기 구조로는 잡을 수 없습니다.

| 유형 | 원문 → 재작성 |
|---|---|
| 방법 격상 | 동료에게 써 보게 하고 의견 받음 → "사용성 테스트를 직접 설계·진행" · 시안 A·B 공유 → "실험" · 두 소재 번갈아 집행 → "A/B 테스트" |
| 하지 않은 행동 추가 | 이미지 12종 제작 → "유관 부서와 요구사항 조율" · 결과 공유 → "우선순위 조정 합의를 이끔" |
| 없는 성과 덧붙임 | 세 단계로 묶음 → "단계별 전환율을 추적할 수 있게" · 화면 재설계 → "과제 성공률을 높여" |
| 도메인·용어 바꿔치기 | 유료 전환 → "구독 전환" · 수업 판매 → "B2B SaaS" · 디자인 담당 → "기획과 디자인" |

판정 기준은 `eval/cases/AUTHORING.md` '판정 기준' — 매칭은 partial 을 인정하고, 재작성에서 partial 의 빠진 핵심을 공고 단어로 채우면 날조입니다.
사람 검수에서 LLM 이 날조라 한 12건을 정상으로 판정한 것은, 원문 사실 안에서 직무 언어로 옮긴 정도의 포장은 허용했기 때문입니다.

### 원인 가설 [자동 + LLM 판정]

재작성 프롬프트(`rewritePrompt`)가 매칭 결과의 full/partial 을 구분하지 않고 같은 "근거"로 넘깁니다.

| 문장이 대응하는 요구사항 | LLM 판정 날조율 | 금지어 포함률 |
|---|---|---|
| partial | 19.1% (9/47) | 17.0% (8/47) |
| full | 4.9% (12/243) | 2.1% (5/243) |

LLM 판정 기준 수치라 사람 보정 전입니다. 개선 실험(4단계)의 대상입니다.

## 4단계 — 원인 하나만 고친 전후 비교

- 바꾼 것: `rewritePromptGraded`(`supabase/functions/job-switch/prompts.ts`). 요구사항에 [직접 근거]/[부분 근거] 표시, 부분 근거에 2단계 판단 이유 전달, 규칙 한 줄. 금지어 예시는 넣지 않음
- 운영(`index.ts`)은 아직 기존 `rewritePrompt` 를 씁니다. 반영 여부는 아래 대가를 보고 따로 정합니다
- 비교: `base-iso` 와 `graded-iso` 각각 **24 케이스 × 2회 = 1,212문장**. 모델·입력·판정 모델 동일
- 재현: `npm run eval:by-level -- --runs=base-iso,graded-iso` · `npm run eval:agreement -- --file=eval/review/judge-human-graded.json`

### 사람 검수로 보정한 날조율 [사람]

개선 후에도 1차와 같은 방식으로 블라인드 검수했습니다(LLM 날조 35 전부 + LLM 정상 1,177 중 무작위 40, 같은 검수자·같은 기준).

| | 개선 전 | 개선 후 |
|---|---|---|
| LLM 판정 정밀도 | 27/39 (69%) | 27/35 (77%) |
| LLM 정상 중 사람 날조 | 4/40 (10%) | **0/40** (95% 상한 8.8%) |
| **보정한 날조율** | **약 14.0%** (보수적 구간 7.3~26.9%) | **약 2.2%** (보수적 구간 1.8~11.0%) |
| 사람이 날조로 본 문장 중 서버 경고 | 3/31 | 5/27 |

- 개선 전 보정치는 1차 검수(1회차 문장)의 비율을 2회 실행 전체에 적용한 값입니다.
- 구간이 겹치는 폭은 작습니다(개선 전 하한 7.3% · 개선 후 상한 11.0%). "날조가 줄었다"는 결론은 구간 끝을 써도 유지되지만, "약 6분의 1"이라는 배율은 표본이 작아 불확실합니다.
- 판정기가 놓친 비율이 4/40 → 0/40 으로 준 것은 유의하지 않습니다(p=0.12). 개선 후에도 판정기가 놓치는 날조가 있을 수 있고, 그 경우 개선 후 날조율은 2.2% 보다 높습니다.

### 대가

- full 대응 문장의 공고 어휘 사용률이 9%p 줄었습니다. 규칙은 partial 만 겨냥했지만 모델이 전반적으로 보수적이 됐습니다.
- full 대응 문장의 날조율(5%)은 바뀌지 않았습니다. 남은 날조는 대부분 full 대응 문장의 행동 추가("함께 확인했고", "합의를 이끌었고")와 용어 격상("디자인 토큰 체계", "스쿼드")입니다. 다음 개선 대상입니다.

### 검수 일관성 메모

같은 원문("단어장 … 3년 동안 구조가 바뀌지 않았습니다")에서 나온 "핵심 기능" 표현 두 문장을 한 번은 정상, 한 번은 날조로 판정했습니다. 검수자 1명의 경계 사례 흔들림으로, 보정치에 미치는 영향은 1건 수준입니다.

## 한계

- 1차 검수·원인 가설 수치는 케이스당 1회 실행 기준입니다. 4단계 비교는 2회 실행 기준입니다.
- 정답 라벨 24개 중 사람이 전체 검수한 케이스는 없고, 요구사항 9개만 사람이 확인했습니다.
- 사람 검수자는 1명입니다. 검수자 간 일치도는 재지 않았습니다.
- 가상 데이터는 한 사람이 쓴 문체라 실제 사용자 포트폴리오의 다양성보다 좁습니다.
- E2E 모드(1단계 포함) 판정은 아직 하지 않았습니다.
- LLM 판정기 정밀도가 69~77% 라, LLM 판정 수치는 절대값보다 같은 조건끼리의 비교에만 씁니다. 절대 수치는 사람 보정치를 씁니다.
- 판정 비용은 Gemini 사전 충전 잔액 차이로 어림한 값입니다(실행 1회분 판정 약 1,700원).
