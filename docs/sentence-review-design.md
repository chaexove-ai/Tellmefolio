# 직무 전환 결과 — 문장별 근거 보기와 채택·수정·되돌리기 (설계)

> 2026-10-16 작성, **미구현**. 대상: `src/pages/jobswitch/JobSwitchResult.tsx`, `src/lib/jobSwitch.ts`.
> 서버 함수와 DB 스키마는 바꾸지 않습니다(→ 4절).

## 1. 왜 필요한가 — 평가 결과가 말해 준 것

`eval/REPORT.md` 의 측정에서 나온 사실 세 가지가 이 설계의 출발점입니다.

| 사실 | 수치 | 화면에 주는 뜻 |
|---|---|---|
| 서버 경고는 실제 날조의 일부만 잡는다 | 사람이 날조로 본 문장 중 경고 3/31(개선 전) · 5/27(개선 후) | **경고 없음 ≠ 안전.** 경고 없는 문장도 근거를 바로 볼 수 있어야 한다 |
| 날조는 근거가 약한(partial) 요구사항 문장에 몰린다 | partial 대응 19.1% vs full 4.9% (LLM 판정, 개선 전) | 서버 경고가 없어도 **"근거 약함"** 을 두 번째 신호로 쓸 수 있다 |
| 놓친 날조는 한글 표현 과장이다 | 행동 추가·방법 격상·성과 덧붙임 | 기계가 못 잡는 부분이라 **사람이 원문과 나란히 보고 고쳐야** 한다 |

지금 화면의 한계(10-16 확인):

- 문장 비교는 원본 **필드 전체**를 옆에 둡니다. 문장이 실제로 인용한 근거 문장(`Sentence.evidence`)은 데이터에 있지만 화면에 쓰지 않습니다.
- 경고는 문장 앞 아이콘 + 밑줄뿐이고, **이유는 사이드바에만** 있습니다.
- 결정은 "버리기 / 전체 저장" 둘뿐입니다. 문장 단위로 고르거나 되돌릴 수 없습니다.
- 경고가 0개면 "원문에 없는 숫자·이름이 들어간 문장이 없습니다"라고만 나와, 전부 안전한 것처럼 읽힙니다.

## 2. 원칙

1. **판단은 사용자 몫, 재료는 우리가 준다.** 문장마다 "무엇을 근거로 썼는지"를 한 번의 클릭으로 보여 줍니다.
2. **기계가 확신하는 만큼만 말한다.** 경고 문구는 "날조입니다"가 아니라 "원문에 없는 숫자 30%" 처럼 사실만. 자동 검사가 무엇을 안 보는지도 적습니다.
3. **되돌리기는 지우기가 아니다.** AI 문장을 거절하면 빈칸이 아니라 **근거 원문 문장으로** 돌아갑니다. 사실을 잃지 않습니다.
4. **막지 않는다.** 확인 안 한 문장이 있어도 저장은 됩니다. 대신 저장 전에 한 번 알립니다.

## 3. 화면

### 3-1. 문장 상태 (아이콘 + 글자, 색만으로 구분하지 않음)

| 상태 | 언제 | 표시 |
|---|---|---|
| **확인 필요** | 서버 경고(`flags`)가 있음 | `AlertTriangle` 갈색 `#8a6a3f` + 문장 뒤 칩 "원문에 없는 숫자 30%" |
| **근거 약함** | 경고는 없지만 대응 요구사항 중 하나가 `partial` | `CircleDashed` `#a8641c`(기존 '일부' 색) + 칩 "근거 약함" |
| 일반 | 위 둘 다 아님 | 아이콘 없음 |
| 채택함 | 사용자가 "그대로 쓰기" | `Check` 초록 `#2f7d57` + "채택" |
| 고침 | 사용자가 문장을 고침 | `PenLine` + "고침" |
| 원문으로 | 사용자가 되돌림 | `Undo2` + "원문" (문장은 근거 원문으로 바뀌어 보임) |

- "근거 약함"은 새로 계산하는 값이 아니라 기존 `matches` 의 `level` 을 문장의 `requirements` 로 따라가 얻습니다.
- 결정한 문장은 경고 아이콘 대신 결정 아이콘을 보여 주되, 경고 칩은 흐리게 남깁니다(무엇을 보고 결정했는지).

### 3-2. 문장을 누르면 — 문장 바로 아래에 펼침

```
┌ 실행 ─────────────────────────────────────────────────────────────┐
│ 원본(필드 전체)          │ ⚠ 두 가지 시안을 Figma 프로토타입으로 제작해   │
│ 시안 두 개를 Figma ...   │   사내 동료 6명을 대상으로 사용성 테스트를     │
│                          │   직접 설계·진행했습니다.  [사용성 테스트]     │
│                          │ ┌ 이 문장의 근거 ─────────────────────────┐ │
│                          │ │ ▍시안 두 개를 Figma 프로토타입으로 만들어 │ │
│                          │ │ ▍사내 동료 6명에게 직접 써 보게 하고      │ │
│                          │ │ ▍의견을 받았습니다.                      │ │
│                          │ │   구매 결제 흐름 개선 · 실행              │ │
│                          │ │                                          │ │
│                          │ │ ◌ 근거 약함 — r4 사용성 테스트 설계·진행  │ │
│                          │ │   AI 판단: 동료 의견 수렴은 있으나 테스트  │ │
│                          │ │   설계 근거는 없음                        │ │
│                          │ │                                          │ │
│                          │ │ 자동 검사는 숫자와 영문 이름만 봅니다.     │ │
│                          │ │ 원문보다 큰 표현이 없는지 직접 확인하세요.  │ │
│                          │ │                                          │ │
│                          │ │ [그대로 쓰기] [고치기] [원문으로 되돌리기] │ │
│                          │ └──────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────────────────┘
```

- **근거**: `Sentence.evidence` 의 id 를 `run.evidence` 로 찾아 원문 문장과 "프로젝트 · 필드"를 인용 블록으로. 커버리지 표의 기존 인용 스타일을 그대로 씁니다.
- **경고 이유**: `flags` 를 사람 말로. 숫자·이름이면 그 토큰을 문장 안에서 형광 표시(`<mark>`)합니다.
- **근거 약함**: 해당 요구사항과 2단계 `why` 를 그대로 보여 줍니다(4단계 개선판이 프롬프트에 넣는 "부족한 점"과 같은 정보).
- 한 번에 한 문장만 펼칩니다. 펼치면 포커스가 패널 첫 버튼으로, 닫으면 문장으로 돌아갑니다(`aria-expanded`, `aria-controls`).

### 3-3. 세 가지 결정

| 버튼 | 동작 | 되돌리기 |
|---|---|---|
| **그대로 쓰기** | 상태만 `accepted` | 펼침 패널의 "결정 취소" |
| **고치기** | 문장 자리가 `textarea` 로 바뀜(원래 AI 문장이 채워진 채). 저장하면 상태 `edited`, AI 원문은 `ai_text` 에 보관 | "AI 문장으로 되돌리기" |
| **원문으로 되돌리기** | 문장을 근거 원문 문장(여러 개면 이어 붙임)으로 바꾸고 상태 `reverted` | "결정 취소" |

- **고친 문장은 다시 검사합니다.** 서버와 같은 숫자·이름 검사(`verifySentences`)를 브라우저에서 돌려, 새로 들어간 숫자가 원문에 없으면 패널 안에 "원문에 없는 숫자 40%가 들어갔어요"를 보여 줍니다. 막지는 않습니다(사용자가 쓴 문장이고, 원문에 안 적었을 뿐 사실일 수 있음).
- 근거 id 가 없는 문장(`no_evidence`)의 "원문으로 되돌리기"는 비활성 + "되돌릴 원문이 없어요. 고치거나 지우세요" 안내, 대신 **지우기**를 보여 줍니다.

### 3-4. 검토 대기열 — 사이드바 "확인 필요"를 바꿉니다

```
확인 필요 · 검토 3 / 9
  ⚠ 원문에 없는 숫자 30%        ✓
  ⚠ 원문에 없는 이름 Amplitude  …
  ◌ 근거 약함 · 사용성 테스트    …
  ...
  [다음 확인할 문장 →]
```

- 대상 = 확인 필요 + 근거 약함. 항목을 누르면 해당 문장으로 스크롤하고 펼칩니다.
- 대상이 0개일 때 문구: "자동 검사에 걸린 문장이 없어요. 자동 검사는 숫자와 영문 이름만 봅니다." (현재 문구 교체)

### 3-5. 저장할 때

- 미결정 대상이 있으면 저장 버튼 옆에 "확인 안 한 문장 N개". 누르면 한 번 묻습니다: **[검토하러 가기] [그대로 저장]**.
- 저장되는 글은 결정을 반영한 최종 문장입니다(`reverted` 는 원문, `edited` 는 고친 문장).
- 저장한 뒤(`saved_portfolio_id` 있음) 결과 화면은 **읽기 전용**입니다. 이후 수정은 편집기에서. 같은 결과를 두 번 저장해 서로 다른 포트폴리오가 생기는 혼선을 막습니다.

## 4. 데이터 — 스키마 변경 없음

`job_switch_projects.sentences`(jsonb) 의 문장 객체에 필드를 **추가만** 합니다. 서버 함수는 이 필드를 쓰지 않으므로 운영 동작이 그대로입니다.

```ts
export interface Sentence {
  text: string;            // 지금 보여 줄 최종 문장
  evidence: string[];
  requirements: string[];
  // ↓ 추가 (없으면 미결정)
  review?: {
    status: "accepted" | "edited" | "reverted" | "deleted";
    ai_text: string;       // 결정 전 AI 문장 — 되돌리기용, 평가 지표용
    at: string;            // ISO
  };
}
```

- 결정할 때마다 해당 프로젝트 행의 `sentences` 와 그 필드의 이어 붙인 글(`context` 등, `joinField` 와 같은 규칙)을 **함께** update 합니다. `saveRunAsPortfolio` 는 이어 붙인 글을 복사하므로 저장 로직은 고치지 않아도 됩니다.
- RLS: `job_switch_projects_own` 이 `for all` 이라 본인 행 update 가 이미 허용됩니다.
- `flags` 의 `sentenceIndex` 는 문장 순서에 기대므로, **문장을 배열에서 빼지 않습니다.** "지우기"는 `status: "deleted"` + `text: ""` 로 두고, 이어 붙일 때 건너뜁니다.

## 5. 측정 — 이 화면이 평가 데이터가 됩니다

결정 기록(`review.status`, `ai_text`)이 쌓이면 사람 검수 없이도 볼 수 있는 지표가 생깁니다.

| 지표 | 뜻 |
|---|---|
| 경고 종류별 되돌림·고침 비율 | 경고가 실제로 문제 문장을 짚는가(정밀도의 실사용 버전) |
| "근거 약함" 문장의 고침 비율 vs 일반 문장 | 두 번째 신호가 의미 있는가 |
| 경고 없는 문장의 고침 비율 | 자동 검사가 놓치는 양의 하한 |

**주의**: 실제 사용자의 문장이므로, 내용은 평가 세트로 가져오지 않습니다(평가 규칙 3). 집계는 개수만, 내용을 보려면 본인 동의 후 `eval/private/` 에서.

## 7. 정하지 않은 것

- **결정 단축키**(예: `1` 채택 / `2` 고치기 / `3` 원문) — 판정기 검수대에서는 유용했지만, 일반 사용자에게는 실수 위험이 있어 보류.
- **문장별 다시 쓰기**("이 문장만 다시") — 모델 호출 비용과 4단계 개선판 반영 여부가 정해진 뒤에.
- **편집기와의 연결** — 저장 후 편집기에서도 문장별 근거를 볼 수 있으려면 `portfolio_projects` 에 근거를 옮겨야 해서 스키마 변경이 필요. 이번 범위 밖.
