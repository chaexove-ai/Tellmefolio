# 자유도 설계 — 템플릿 + 알파

작성 2026-09-22 · `docs/editor-redesign.md` 에 이어지는 문서

---

## 1. 왜 이 문서가 필요한가

사용자의 말:

> 아무리 생각해도 자유로운 툴이 없으면 사람들의 선호도와 취향이 너무 다르기
> 때문에 안 쓸 거 같긴 해. 물론 다양한 템플릿이 있는 것은 너무 좋지.
> 여기에 플러스 알파로 자유성을.

맞는 지적입니다. 템플릿 4종 × 설정 몇 개로는 취향을 담을 수 없고, 담기지
않으면 사람들은 피그마나 노션으로 돌아갑니다.

앞선 문서에서 자유 배치를 두 번 접었는데, 그 반대 이유는 전부
**"페이지 전체가 절대 좌표가 되면"** 에 걸려 있었습니다. 자유도 자체가
아니라 그 구현 방식이 문제였습니다. 쓰는 사람 입장에서는 결과가 같았고요.

이 문서는 **다시 흐르는 것을 유지하면서 자유도를 얼마나 열 수 있는지**를
정리합니다.

---

## 2. 자유도의 네 층위

아래로 갈수록 자유롭고, 아래로 갈수록 무겁습니다. 전부 다시 흐릅니다.

| | 층위 | 무엇 | 무게 |
|---|---|---|---|
| 1 | **블록 조작** | 순서·숨김·폭·이미지 크기 | 작음 |
| 2 | **블록 추가** | 원하는 블록을 원하는 자리에: 텍스트·이미지·인용·구분선·2단·임베드 | 중간 |
| 3 | **스타일 열기** | 강조색, 제목/본문 서체 분리, 모서리, 섹션 간격 | 작음 |
| 4 | **자유 배치 블록** | 블록 하나가 캔버스. 그 안에서 겹치고 돌리고 마음대로 | 큼 |

1은 `editor-redesign.md` 6절에 이미 있습니다. 이 문서는 2·3·4를 다룹니다.

**2가 체감상 가장 큽니다.** "다섯 칸을 채우는 화면"이 "원하는 걸 쌓는
화면"으로 바뀌는 지점이라, 정형화 느낌이 여기서 풀립니다. 4는 차별점이지만
2 없이 4만 있으면 여전히 "정해진 틀 + 그림 한 장"입니다.

## 3. 블록 — 데이터 모델

```sql
create table public.portfolio_blocks (
  id uuid primary key default gen_random_uuid(),
  portfolio_id uuid not null references public.portfolios(id) on delete cascade,
  -- null 이면 포트폴리오 직속 블록(소개·연락처 같은 것),
  -- 값이 있으면 그 프로젝트에 붙는 블록.
  project_id uuid references public.portfolio_projects(id) on delete cascade,
  position int not null default 0,
  kind text not null,
  span text not null default 'full',   -- 'full' | 'half'
  data jsonb not null default '{}',
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

`kind`: `text` · `image` · `quote` · `divider` · `columns` · `embed` · `canvas`

### 3.1 왜 jsonb 인가

블록 종류마다 필요한 값이 전혀 다릅니다. 컬럼으로 펼치면 비어 있는 칸이
서른 개인 테이블이 됩니다. `data` 는 열어두고 검증은 애플리케이션이 합니다.

대가는 DB가 내용을 지켜주지 않는다는 것입니다. 그래서 **읽을 때 기본값으로
감싸는 파서를 반드시 한 곳에 둡니다** — 화면 여기저기서 `data.items?.[0]?.x`
같은 걸 하기 시작하면 손쓸 수 없어집니다.

### 3.2 기존 5필드는 그대로 둡니다 — 이게 핵심 결정입니다

블록은 **더하는 것**이지 5필드를 대체하지 않습니다.

- 프로젝트는 여전히 `depth` 에 따라 5필드를 그리고, **그 뒤에** 블록을 그립니다
- AI 초안 생성은 계속 5필드 컬럼에 씁니다
- 직무 전환 재구성도 5필드를 다시 씁니다

5필드를 블록으로 옮기는 마이그레이션은 **하지 않습니다.** 위험만 크고
사용자가 얻는 게 없습니다. 나중에 블록이 자리를 잡으면 그때 5필드를
`kind='text'` + 고정 라벨로 흡수할 수 있고, 그건 그때 결정합니다.

## 4. 자유 배치 블록

### 4.1 무엇인가

한 블록이 고정 비율의 캔버스입니다. 그 안에서는 이미지·텍스트·도형을
마음대로 놓고, 겹치고, 돌립니다. 바깥에서 보면 흐름 안에 얹힌 그림
한 장입니다.

**슬라이드 한 장을 문서 중간에 끼워 넣는 구조**라고 보면 정확합니다.

### 4.2 왜 이건 되는가

캔버스가 **통째로 비율을 유지하며 줄어들기** 때문입니다.

| 걱정했던 것 | 캔버스 블록에서는 |
|---|---|
| 폰에서 무너짐 | 캔버스 전체가 화면 폭에 맞춰 축소. 안쪽 배치는 그대로 |
| PDF 페이지 나눔 | 블록 하나가 한 덩어리라 계산할 게 없음 |
| 번역 시 넘침 | 캔버스 안 글자는 기본으로 번역하지 않음 (4.5) |
| 직무 전환이 못 들어감 | 재구성은 5필드와 텍스트 블록에만. 캔버스는 "내가 만든 그림" |
| 템플릿이 죽음 | 캔버스는 블록 하나. 나머지는 여전히 템플릿이 그림 |

### 4.3 데이터

```jsonc
{
  "aspect": "16:9",            // 16:9 | 4:3 | 1:1 | 3:4
  "bg": "#ffffff",             // null 이면 투명
  "items": [
    {
      "id": "a1",
      "type": "image",          // image | text | shape
      "src": "<storage path>",
      "x": 4, "y": 6,           // 캔버스 폭/높이에 대한 %
      "w": 44, "h": 52,         // %
      "rot": -2,                // deg
      "z": 1,
      "fit": "cover",
      "radius": 8               // px 아님 — 캔버스 폭 대비 비율로 환산
    },
    {
      "id": "a2",
      "type": "text",
      "text": "브랜드 아이덴티티",
      "x": 52, "y": 20, "w": 40,
      "rot": 0, "z": 2,
      "size": 4.5,              // 캔버스 폭의 % (px 아님)
      "weight": 600,
      "align": "left",
      "color": "#1a120d"
    }
  ]
}
```

**좌표와 글자 크기를 전부 %로 둡니다.** px 로 두면 축소할 때마다 환산이
필요하고, 그 환산이 화면·PDF·공개 링크에서 제각각 틀어집니다. %는 어디서
그리든 같은 그림이 나옵니다.

### 4.4 렌더링 — 여기가 유일한 기술적 위험

캔버스를 어떻게 축소할지 두 가지 길이 있고, **둘 다 html2canvas(PDF)에서
검증해야 합니다.** 이게 이 기능에서 유일하게 "해봐야 아는" 부분입니다.

**A. `aspect-ratio` + % 배치 + 컨테이너 단위(`cqw`)**
- 순수 CSS. 자바스크립트 계산이 없어 가장 깔끔
- 위험: `cqw` 를 html2canvas 가 제대로 읽는지 확인된 바 없음

**B. 고정 내부 좌표 + `transform: scale()` + 래퍼 높이 계산**
- 내부는 예를 들어 1200×675 고정, 컨테이너 폭을 재서 `scale`
- `transform: scale` 은 레이아웃 크기를 안 줄이므로 래퍼 높이를
  `h × scale` 로 직접 지정해야 합니다 (EditorPreview 에서 겪은 것과 같은 함정)
- 위험: 래퍼 높이 계산이 어긋나면 아래에 빈 공간이 생김

**먼저 할 일은 둘 중 하나를 고르는 게 아니라, 작은 프로토타입으로
html2canvas 캡처를 비교해 보는 것입니다.** 여기서 틀리면 나중에 전부
다시 짜야 합니다.

### 4.5 번역

캔버스 안 텍스트는 **기본으로 번역하지 않습니다.** 고정 박스 안의 글자는
길이가 20~30% 늘면 그대로 넘칩니다.

블록마다 `번역 포함` 체크를 두되 기본은 꺼둡니다. 켜면 번역 후 그 블록만
눈으로 확인하라고 안내합니다. 조용히 망가지는 것보다 켜고 확인하는 편이
낫습니다.

### 4.6 편집은 어디서 하는가

**전체화면에서 합니다.** 오른쪽 패널의 미리보기는 폭이 좁아 캔버스를
만질 수 없습니다. 이미 만들어둔 "크게 보기"를 편집 모드가 있는 화면으로
키웁니다.

최소 조작: 끌어 옮기기 · 모서리로 크기 · 회전 핸들 · 앞뒤 순서 ·
삭제 · 실행취소. **스냅과 정렬 가이드는 1차에 넣지 않습니다** — 없어도
쓸 수 있고, 있으면 잘 만들어야 해서 비용이 두 배가 됩니다.

## 5. 스타일 열기

템플릿 4종은 "잘 만들어진 출발점"으로 두고, 그 위에 포트폴리오별로
덮어쓸 수 있게 합니다.

```sql
alter table public.portfolios
  add column if not exists style_overrides jsonb not null default '{}';
```

열 값: 강조색 · 제목 서체(본문과 분리) · 모서리 반경 · 섹션 간격.

**한 번에 다 열지 않습니다.** 강조색 하나만 열어도 체감이 큽니다. 반대로
전부 열면 "탁한 색" 사고가 사용자 손에서 반복됩니다 — 템플릿이 보장하던
대비가 깨집니다. 그래서 **색은 고르는 방식으로만 엽니다**(자유 색상환이
아니라 검증된 팔레트 중 선택).

## 6. 깨뜨리면 안 되는 것 (재확인)

`editor-redesign.md` 7절과 같습니다. 각 단계 끝에 확인합니다.

- [ ] **한/영 전환** — 캔버스 블록은 기본 미번역. 나머지는 다시 흐른다
- [ ] **PDF** — 미리보기와 파일이 같다. 캔버스 블록이 빈칸으로 나오지 않는다
- [ ] **공개 링크 모바일** — `/p/:id` 를 폰에서 열어 읽을 수 있다
- [ ] **직무 전환** — 재구성 내용이 5필드·텍스트 블록에 들어간다

## 7. 구현 순서

| 단계 | 내용 | 마이그레이션 |
|---|---|---|
| 1 | `portfolio_blocks` 테이블 + `text` · `image` · `divider` | 테이블 |
| 2 | 블록 순서·숨김·폭 (`editor-redesign.md` 6.2와 합류) | — |
| 3 | `quote` · `columns` · `embed` | — |
| 4 | **캔버스 렌더링 프로토타입** — A안/B안을 html2canvas 로 비교 | — |
| 5 | `canvas` 블록 편집기 (전체화면) | — |
| 6 | 스타일 열기 — 강조색부터 | `style_overrides` |

4단계는 **결과물이 없는 단계**입니다. 화면에 아무것도 안 생기지만
건너뛰면 5단계를 두 번 만들게 됩니다.

## 8. 결정 기록 — 왜 페이지 전체 캔버스가 아닌가

`editor-redesign.md` 2절의 표가 여전히 유효합니다. 이 문서가 더하는 구분은
하나입니다.

> **자유 배치를 블록 하나 안에 가두면, 그 표의 다섯 가지가 전부 살아난다.**

페이지 전체가 절대 좌표면 다시 흐를 수 없습니다. 블록 하나가 절대
좌표이고 그 블록이 통째로 축소되면, 바깥은 여전히 다시 흐릅니다.

그래서 다음에 "페이지 전체를 캔버스로" 얘기가 또 나오면, 답은 "안 된다"가
아니라 **"캔버스 블록을 전체폭으로 놓고 세로로 이어 붙이면 사실상 그
모양이 된다"** 입니다. 같은 것을 원하면서 다시 흐르는 성질을 잃지 않는
방법이 이미 있습니다.
